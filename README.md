# Stock Screener

Локальный рыночный сканер на Rails 8.1 / Ruby 4.0.1, PostgreSQL 16, Hotwire и Solid Queue. Данные поступают напрямую из T-Invest API. Агент и MCP в сборе данных не участвуют. Торговых операций в коде нет.

## Запуск

```sh
# .env уже создан локально; в новом клоне скопировать .env.example и заполнить ключи.
make up
# http://localhost:3002
make logs
make test
make down
```

`make down` сохраняет базу. Проект имеет отдельный Docker Compose project `stock_screener`, отдельную базу и порт 3002, поэтому может работать одновременно с trading. Привязка порта — только 127.0.0.1. Это локальная однопользовательская версия без публичной регистрации/авторизации.

Токен Т-Инвестиций хранится в `.env` с правами 0600, исключён из Git и Docker build context. `INTERNAL_API_TOKEN` защищает канал сборщик → Rails. Не выводить содержимое `.env` в логи. После изменения токена выполнить `docker compose up -d --force-recreate web worker collector`.

## Как пользоваться

В самом приложении доступна [FAQ](http://localhost:3002/guide): чекбоксы, обновление истории, расчёты объёма и уровней, условия сигналов и частые вопросы. Ссылка находится внизу бокового меню, над «Т-Инвестиции API».

1. Нажать «Добавить инструмент», ввести тикер, выбрать нужный результат и класс торгов. Поддерживаются акции и конкретные фьючерсные контракты. Сохраняется UID из API, а не только тикер. Истёкшие фьючерсы исключаются из сбора; автоматического перехода на следующий контракт нет.
2. В таблице три независимых настройки: общий сбор, аномальные объёмы, пробои D/W. Общий выключатель приостанавливает наблюдение. Сборщик применяет список в течение 10 секунд.
3. В карточке инструмента — переключатель «День / Неделя», вся загруженная история свечей выбранного периода, параметры детектора объёма, автоматические кандидаты уровней и добавление ручного уровня. Ручной уровень можно задать отдельно для D или W. Оба вида уровней доступны на графике. Начальная дневная шкала цены подстраивается под видимые свечи; полный обзор по двойному щелчку учитывает все активные уровни, даже за пределами диапазона свечей.
4. Сигналы появляются в ленте; главная страница обновляется каждые 5 секунд. Токен браузеру не передаётся. Сбор продолжается при закрытой вкладке, пока работает Docker и компьютер не спит.

Перетаскивание за значок ⠿ справа в строке меняет порядок инструментов. С клавиатуры: Tab до значка, затем клавиши вверх/вниз. Он сохраняется после обновления страницы; новые бумаги добавляются в конец. Перестановка не перезапускает рыночный поток.

## Правила первой версии

### Аномальный объём

Биржевые сделки агрегируются в минутные интервалы. BUY, SELL и неопределённое направление сохраняются отдельно. Единица объёма — лоты API; цена фьючерса отображается в пунктах, без некорректного пересчёта в рубли.

Сигнал: объём завершённой минуты не меньше заданного абсолютного минимума и не меньше медианы предыдущих 20 полных минут, умноженной на порог (по умолчанию ×3). Текущая минута в базу не входит. Первая неполная минута, интервалы до подписки и разрывы соединения исключаются. После изменения набора подписок или переподключения база набирается заново. Первое возможное событие — после 21 полной минуты.

Для запоздавших сделок предусмотрено окно 30 секунд, минута финализируется через 35 секунд после её окончания. Слишком старые события отбрасываются. Снимки минут идемпотентны. Сохраняются минутные агрегаты за 7 дней, а не полная лента сделок.

Это начальный детектор относительно недавней активности, без поправки на время суток и отдельные торговые сессии. Он требует проверки качества на накопленных данных; разные акции и фьючерсы требуют разных порогов.

### Уровни D/W

История: год дневных и два года недельных завершённых свечей. Она обновляется при добавлении инструмента, вручную и раз в час через Solid Queue. Незавершённые свечи API в расчёт не попадают.

Автоматические **зоны** строятся отдельно для D/W по экстремумам тела или тени среди пяти свечей. Нужны ATR14 и две завершённые свечи справа (минимум 16 свечей истории). Реакция — меньшее благоприятное удаление двух следующих закрытий от экстремума; минимум 0,25 ATR. Область включает часть тени до тела (до 0,6 ATR) и по 0,15 ATR с каждой стороны. Пересекающиеся области одного типа объединяются при общей ширине до 1,5 медианного ATR касаний. Новый подход учитывается через минимум три свечных интервала и после ухода закрытия от предыдущей области минимум на 0,5 ATR.

Два независимых подхода дают подтверждённую зону. Одна сильная реакция даёт **предварительную**: от 2 ATR либо от 1 ATR при RVOL ≥ 1,5. Предварительные зоны видны, но не создают сигналов. Ширина, пороги и баллы — исходные эвристики, без заявленной доходности; нужен последовательный бэктест и проверка на других инструментах.

RVOL — объём / медиана предыдущих 20 сопоставимых свечей. Для D отдельно сравниваются будни и выходные по Москве, для W — недели. Текущая свеча исключена; неполная база, пропуски или нулевая медиана дают отсутствие оценки. Это **не полноценный торговый календарь**: праздники и сокращённые сессии пока не выделяются. Минутный детектор остаётся отдельным и использует прежние 20 непрерывных минут.

Баллы касания: `(1 + clamp(RVOL − 1, 0, 2) + min(реакция_ATR, 2)) / (1 + возраст / 20)`. Неизвестный RVOL даёт нулевой бонус. Возраст начинается после подтверждения двумя свечами. Сила, давность и расстояние до последней цены отображаются отдельно. Объём всей свечи не является объёмом по цене уровня.

Сила в таблице — относительная: низкая, средняя или высокая среди активных подтверждённых автоматических зон той же бумаги, периода и текущей версии расчёта. Используется ранг баллов: нижняя треть — низкая, верхняя — высокая, середина — средняя; равные баллы получают средний ранг и одинаковую оценку. При менее чем трёх сравнимых зонах показывается «Мало уровней», сами баллы остаются видимыми. Предварительные зоны, открытые пробои, ручные уровни и записи без актуальной оценки в сравнение не входят. Глазик не влияет на оценку; удаление или появление других зон может изменить относительную категорию. Это не абсолютная сила и не вероятность удержания/пробоя.

Выбираются до 12 зон по баллам на период. Совпадение — пересечение границ с той же исходной ролью. Границы и оценка совпавшей зоны обновляются; выпавшие автоматические зоны архивируются. Архивные могут вернуться в отбор; скрытые пользователем совпавшие зоны остаются скрытыми. Глазик в строке переключает видимость зоны на графике: строка, расчёты и сигналы сохраняются. Настройка хранится в БД и остаётся при обновлении истории и переключении D/W. Видимость меняется без перезагрузки, с сохранением масштаба и прокрутки; ценовая шкала остаётся прежней. «Удалить уровень» (корзина) по-прежнему отключает автоматический уровень или удаляет ручной. Незавершённые сценарии пробоя не архивируются и сохраняют границы, поэтому временно возможны дополнительные зоны сверх 12. Ручные линии автоматический пересчёт не меняет.

На графике показаны все активные зоны D/W, объёмы и EMA: 20/50/200 на днях, 20/40 на неделях. EMA стартует с SMA первых N закрытий; пока свечей меньше N, линии нет. EMA поясняет контекст, не фильтрует сигналы. ATR14 использует true range и сглаживание Уайлдера. Текущая цена — пунктирная линия и отметка справа по последней сделке сборщика. Она обновляется каждые 5 секунд без сброса масштаба; при отсутствии сделок более двух минут отметка жёлтая, время сделки доступно при наведении (МСК). Если цена вне видимой шкалы, подпись со стрелкой показана у её края без горизонтальной линии. Пока котировки нет, отметка не показывается. Перекрестие показывает дату, цену (до десятых) и объём свечи. Колёсико увеличивает участок вокруг курсора, перетаскивание двигает график по времени и цене. В области объёмов масштабирование и движение затрагивают только время. Двойной щелчок сбрасывает вид. С клавиатуры на графике работают +/−, стрелки и Home. Перемещение ограничено загруженной историей; полный обзор показывает все уровни, при увеличении остаётся выбранный участок. При открытии карточки и выборе 1D видны последние два календарных месяца относительно последней загруженной свечи; если истории меньше — вся доступная. Начальная шкала цены подстраивается под минимумы и максимумы видимых свечей с отступом 6% с каждой стороны; далёкие уровни и EMA её не растягивают. Более ранние свечи доступны при перемещении и уменьшении масштаба, а двойной щелчок возвращает всю историю. При выборе 1W отображается вся недельная история. Цвет объёма — направление свечи, не BUY/SELL.

Фильтр «Сила» над графиком позволяет выбрать несколько категорий чекбоксами: высокую, среднюю, низкую силу и зоны без оценки (включая предварительные, ручные, открытые пробои и недостаток сравнимых зон). Чекбокс «Все уровни» включает или снимает все категории; без выбранных категорий уровни на графике скрыты. Фильтр относится только к графику и не меняет таблицу, расчёты или сигналы. Уровень виден, только если подходит фильтру и включён глазик. Выбор запоминается отдельно для каждой бумаги в текущей вкладке браузера, в том числе при переключении D/W и обновлении страницы. Масштаб и прокрутка при выборе фильтра сохраняются.

### Жизненный цикл пробоя

- **Пересечение** — свежая цена прошла внешнюю границу плюс буфер **0,1 ATR** для автоматической зоны; для ручной линии остаётся **0,1% цены**. Минимальный автоматический буфер 10⁻⁹ — точность хранения, не биржевой шаг. Нужна предыдущая свежая цена; пауза между событиями одной зоны — 6 часов. Предварительные зоны и открытые сценарии не создают ранних пересечений.
- **Закрытие за зоной** (`confirmed`) — переход закрытий через границу с буфером начинает сценарий. Границы и буфер фиксируются, EMA-контекст сохраняется в событии. D проверяется по D, W по W.
- **Возврат** (`failed_breakout`) — последующее закрытие вернулось внутрь зоны или прошло её насквозь. Сценарий завершён, прежняя роль сохраняется.
- **Ретест** (`retest`) — последующая свеча коснулась пробитой границы с допуском буфера и закрылась за буфером. Роль меняется: сопротивление становится поддержкой или наоборот.
- **Удержание** (`held_breakout`) — минимум 5 последующих свечей без возврата и закрытие за буфером также меняют роль. Закрытие в полосе буфера не считается удержанием.

Сохранённые события не переписываются. У существующих зон последовательно проверяются новые свечи после регистрации; курсор и ключ события защищают от дублей. После простоя в ленте может появиться отложенное событие с датой свечи. Новым зонам и при миграции старых уровней прошлые пробои не приписываются. Когда выключенная проверка проходит обновление истории, ожидающий сценарий отменяется без события, курсор продвигается.

Пересчёт зон по сохранённым свечам без API и исторических сигналов: `docker compose exec web bin/rails levels:rebuild`. Пересчёт продвигает курсор обработки существующих зон; применять после обычного обновления, если нужно сохранить обработку пропущенных пробоев. Открытый сценарий пересчёт не меняет.

Стакан, Volume Profile, внутридневная сезонность, Telegram/звук, агентский разбор и автоматические сделки в эту версию не входят.

## Процессы и код

- `web` — Rails, интерфейс и защищённый внутренний API.
- `worker` — Solid Queue: история и построение уровней.
- `collector` — Node.js 22 без npm-зависимостей: официальный WebSocket T-Invest, heartbeat, переподключение, агрегаты. Все бизнес-правила находятся в Rails.
- `db` — PostgreSQL, отдельный именованный Docker volume.

В первой версии максимум 100 инструментов. Сборщик подписывается только на биржевые сделки. Один недоступный инструмент может отклонить подписку; причина видна в статусе потока. Удалите/выключите недоступный инструмент и повторите подключение.

## Проверки

`make test` запускает Rails/RSpec, тесты Node-сборщика и JavaScript-тесты геометрии графика (`make chart-test`). Rails-спеки находятся в `spec/`, тесты JavaScript-сборщика — в `collector/aggregator.test.mjs`. Проверяются разрывы/прогрев, неизвестная сторона, пороги объёмов, идемпотентность, stale prices, раздельные чекбоксы, D/W-подтверждения, отсутствие исторических сигналов при добавлении уровня и рендер графика.

Отдельные наборы и конкретные спеки:

```sh
make rspec
make rspec spec=spec/services/detectors/volume_spec.rb
make rspec spec='spec/requests --format documentation'
make collector-test
```

RSpec использует отдельную тестовую базу и откатывает изменения после каждого примера. Запросы к Т-Инвестициям в спеках фоновой задачи подменяются проверяемым двойником клиента; реальный токен для тестов не нужен.

Необязательные read-only проверки с реальным API:

```sh
docker compose exec web bin/rails runner script/check_api.rb
docker compose exec web bin/rails runner script/check_history.rb
docker compose run --rm --no-deps collector node collector/check_connection.mjs
```

Проверка истории использует временную запись и откатывает транзакцию. Скрипт проверки потока подписывается на SBER, проверяет подтверждение и ping, затем закрывает соединение.
